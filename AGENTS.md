# AGENTS.md — правила разработки «Лесной школы»

## Назначение проекта

Это статический детский мини-сайт с тремя законченными играми по русскому языку для детей 6–8 лет. Приложение работает без сервера и обязательной сети, локально запускается через Vite и позднее публикуется в GitHub Pages через GitHub Actions.

## Обязательный продуктовый состав

- На главной странице ровно три карточки: логотип, название, описание, «Как играть» и «Играть».
- В каждой игре один основной режим и сессия из 10 уникальных заданий.
- «Лягушка на болоте»: словарное слово с пропуском, семь медленно летающих 3D-мух со случайными буквами на светлом брюшке, сгенерированный естественный язык и выбранная пользователем 3D-лягушка `frog-character-v3.png`. Сверху расположена дорожка из 10 кружков к отдельной короне.
- «Белочка и кладовая»: определение 1/2/3 слогов; белочка должна заметно переносить орех в выбранный сундук.
- «Бобёр строит мост»: сборка предложения по порядку; брёвна цилиндрические с круглыми торцами, бобёр двигается и укладывает их в мост.
- Ошибка не завершает задание. Итоговый процент считается по ответам, данным верно с первой проверки.
- За сессию выдаётся 1 сердце при результате ниже 75%, 2 сердца при 75–99%, 3 сердца при 100%.
- Один профиль хранится под ключом `forest-school:v1`: имя, сердца, история, настройки звука и один из 20 уровней оформления.

## Архитектурные границы

```text
src/app/                 оболочка, главная, профиль, выбор игры
src/shared/              типы, localStorage, награды, звук, общие UI
src/games/frog/          только лягушка: components/data/assets/audio/styles/tests
src/games/squirrel/      только белочка: components/data/assets/audio/styles/tests
src/games/beaver/        только бобёр: components/data/assets/audio/styles/tests
```

- Игровые директории не импортируют друг друга.
- Педагогические данные не размещать внутри UI-компонентов.
- Общую логику выносить в `shared` только при реальном использовании несколькими играми.
- Не добавлять backend, базу данных, аккаунты, внешние CDN или обязательные сетевые запросы.
- Не смешивать ассеты, стили и звуковые темы разных игр.

## Визуал и взаимодействие

- Сохранять яркий современный детский стиль, крупные зоны нажатия и читаемую кириллицу.
- Фоны каждой игры — локальные WebP в её `assets`; персонажи и игровые предметы — SVG/CSS или локальные изображения.
- Персонажи не должны быть статичной декорацией: каждое верное действие сопровождается понятным движением.
- В игре лягушки корпус всегда показан со спины и остаётся неподвижным. Слежение использует таблицу 6×2: шесть сгенерированных задних PNG (три угла × два уровня взгляда) и шесть зеркальных состояний дают 12 направлений курсора. Запрещены CSS-вращение, наклон, смещение и пружинное качание большой лягушки. Язык находится под слоем персонажа, вычисляется от скрытой точки рта до фактического центра мухи, захватывает правильную муху и втягивает её.
- Верный ответ двигает маленькую лягушку на один из 10 кружков к короне, ошибка отодвигает на один кружок назад. Ошибка на нулевой позиции немедленно завершает игру поражением.
- Финальные растровые спрайты лягушки, короны, языка и мухи хранятся только в `src/games/frog/assets`; буква мухи остаётся динамическим HTML-текстом для случайной генерации и доступности.
- Управление обязано работать мышью, клавиатурой и Pointer Events/touch; drag всегда дублируется нажатием.
- Минимальная ширина — 360 px. Проверять desktop, мобильный портрет и альбомную ориентацию.
- Уважать `prefers-reduced-motion`; смысл обратной связи не должен зависеть только от цвета, звука или анимации.

## Звук и данные

- Использовать общий Web Audio-менеджер и отдельную тему каждой игры.
- AudioContext запускать только после действия пользователя.
- Всегда оставлять выключатель и отдельную громкость музыки/эффектов.
- Повреждённый `localStorage` не должен ломать приложение.
- Незавершённая сессия не сохраняется и не начисляет награду.

## Команды и критерии готовности

Перед завершением изменения выполнить:

```bash
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run build
```

- Unit-тесты покрывают награды, профиль, банки заданий и уникальность выборки.
- Component-тесты покрывают критические формы и состояния UI.
- Playwright проверяет три карточки и три игры на desktop/mobile.
- Не считать задачу законченной, если хотя бы одна игра является макетом или персонаж не реагирует на действия.

## GitHub Pages

- Сейчас не публиковать и не добавлять remote без прямого запроса пользователя.
- Сборка должна оставаться статической в `dist`.
- Для project site использовать `VITE_BASE_PATH=/<repository>/`.
- Будущий workflow: `npm ci` → `npm run build` → публикация `dist` через GitHub Pages.
