# Лесная школа — инструкция по реализации

## 1. Цель и формат

«Лесная школа» — статический мини-сайт с тремя законченными играми по русскому языку для детей 6–8 лет. Итоговый продукт должен запускаться локально, собираться Node.js/Vite в папку `dist` и быть готовым к будущей публикации на GitHub Pages.

Обязательные требования преподавателя:

- на главной странице представлены ровно три игровые карточки;
- каждая карточка имеет собственный логотип-изображение, описание, кнопку «Играть» и кнопку «Как играть»;
- используются изображения, звук и заметные анимации;
- все игры проходимы и не являются макетами;
- механики не повторяют игры из преподавательского примера;
- интерфейс аккуратный, адаптивный и работает с мышью, клавиатурой и touch.

## 2. Пользовательский путь

1. При первом открытии ребёнок вводит имя длиной до 24 символов.
2. Профиль сохраняется в `localStorage` и открывает главную лесную карту.
3. Ученик выбирает одну из трёх карточек, при необходимости читает инструкцию.
4. Каждая карточка сразу открывает единственный основной режим своей игры.
5. Сессия содержит 10 уникальных заданий. Ошибка не завершает задание: ребёнок пробует снова, но балл «с первой попытки» уже не начисляется.
6. После десятого задания показываются процент, 1–3 сердца и три действия: повтор, другая игра, главная.
7. Завершённая сессия записывается в профиль. Незавершённая не сохраняется.

## 3. Профиль и награды

Ключ хранилища — `forest-school:v1`. Поддерживается один профиль. Можно изменить имя или после подтверждения полностью удалить данные.

```ts
interface StudentProfile {
  version: 1
  name: string
  createdAt: string
  totalHearts: number
  appearanceTier: number
  sessions: SessionRecord[]
  audio: { enabled: boolean; music: number; effects: number }
}

interface SessionRecord {
  id: string
  gameId: 'frog' | 'squirrel' | 'beaver'
  gameTitle: string
  modeId: string
  modeTitle: string
  completedAt: string
  correct: number
  total: 10
  percent: number
  hearts: 1 | 2 | 3
}
```

Формула: 0–74% — одно сердце, 75–99% — два, 100% — три. Каждые пять суммарных сердец дают уровень оформления, максимум — 20-й уровень на 100 сердцах. Последовательность: серебряная веточка, золотой листок, контур имени, сияние, листья, жёлуди, светлячки, лесной знак, искры, изумрудная рамка, папоротник, звёздная пыль, жемчужные буквы, грибная поляна, северное сияние, кристаллы, дух леса, корона, радужная рамка, статус «Хранитель леса». После 100 счёт растёт, оформление остаётся максимальным.

При битом JSON, неверной версии или неполных полях приложение не падает: предлагает создать профиль заново. Громкость дополняется безопасными значениями по умолчанию.

## 4. Три игры и три основных режима

### Лягушка на болоте

Один режим «Словарные слова». На кувшинке видно слово с одной пропущенной буквой и смысловая подсказка. По сцене плавно летают семь 3D-мух со случайными буквами на светлом брюшке. Используется выбранный пользователем образ `frog-character-v3.png`: большая лягушка всегда сидит спиной к ребёнку и не качается. Курсор выбирает одно из 12 устойчивых задних состояний: три угла влево и их отражения вправо на двух уровнях взгляда. Шесть исходных PNG создаются ImageGen, ещё шесть получаются зеркально; CSS-вращение и смещение персонажа не используются. Язык рендерится под персонажем, поэтому его основание скрыто корпусом и визуально появляется изо рта; правильная муха прилипает к кончику и втягивается. Вверху находится дорожка из 10 кружков: верный ответ передвигает маленькую лягушку к отдельной 3D-короне, ошибка возвращает на шаг назад, а ошибка на нулевой позиции завершает игру поражением.

### Белочка и кладовая

Один режим «Сколько слогов?». Объект-орех показывает картинку и слово. Ребёнок прохлопывает слово и выбирает один из трёх сундуков: 1, 2 или 3 слога. Ответ задаётся нажатием или перетаскиванием. При верном ответе белочка берёт орех, пробегает к нужному сундуку, его крышка открывается, а орех исчезает внутри. При ошибке персонаж остаётся на месте и предлагает прохлопать слово снова.

### Бобёр строит мост

Один режим «Собери предложение». Слова представлены масштабируемыми цилиндрическими брёвнами с круглыми торцами. Ребёнок передаёт их бобру по порядку, может вернуть уже выбранное бревно и затем проверяет готовое предложение. Бобёр двигается вдоль строящегося моста, несёт очередное бревно и после верной проверки перебегает на другой берег.

## 5. Архитектура

Стек: React, TypeScript, Vite, Motion, Web Audio, Vitest, Testing Library и Playwright. Сервер, API, база данных, аккаунты, внешние CDN и обязательная сеть отсутствуют.

```text
src/app                 оболочка, главная, профиль
src/shared              типы, localStorage, звук, сессия, общие UI
src/games/frog          код, контент, стили, звук и фон лягушки
src/games/squirrel      код, контент, стили, звук и фон белочки
src/games/beaver        код, контент, стили, звук и фон бобра
```

Игровые папки не импортируют друг друга. Общий контроллер знает только ход сессии и число правильных ответов; педагогические правила остаются внутри игрового модуля. Библиотеки заданий отделены от компонентов.

## 6. Изображения, анимация и звук

- У каждой игры собственный оптимизированный WebP-фон без текста.
- Персонажи, логотипы и интерактивные объекты выполнены локальными оптимизированными PNG с прозрачностью и SVG/CSS; исходные технические фоны генерации в production не включаются.
- Лягушка `frog-character-v3.png`, корона, язык и муха созданы встроенным генератором изображений в мягком 3D-сказочном стиле. Буквы не запекаются в картинку мухи, а накладываются программно на брюшко.
- Анимации показывают действие, верный ответ, ошибку и переход между заданиями.
- Музыка и эффекты создаются Web Audio. Браузерный AudioContext запускается только после пользовательского действия.
- Есть общий выключатель и раздельная громкость музыки и эффектов.
- При `prefers-reduced-motion` длительные и повторяющиеся движения сокращаются.

## 7. Адаптивность и ошибки

- Минимальная ширина — 360 px, обязательны портретный и альбомный режимы.
- Зоны нажатия — минимум 44×44 px, фокус клавиатуры хорошо виден.
- Drag-and-drop дублируется нажатием, поэтому мобильная игра не зависит от HTML DnD.
- Правильность обозначается не только цветом, но и текстом, движением и звуком.
- Выход из незавершённой игры не создаёт запись и не начисляет сердца.
- Отсутствие Web Audio, отключённый звук или reduced motion не блокируют задания.

## 8. Проверка готовности

- `npm run typecheck` — строгая проверка TypeScript.
- `npm run lint` — статический анализ.
- `npm test` — формула наград, профили, банки и уникальность сессий.
- `npm run test:e2e` — welcome, карточки, инструкции, три игры и мобильный viewport.
- `npm run build` — production-сборка в `dist`.
- `npm run preview` — локальная проверка итоговой сборки.

Продукт готов, когда все три основных режима можно пройти, сессия выдаёт корректную награду, профиль переживает перезагрузку, а интерфейс остаётся пригодным на 360 px и desktop.

## 9. Будущая публикация

На текущем этапе GitHub Actions и публикация не создаются. Позже `VITE_BASE_PATH` задаётся как `/<repository>/`, а GitHub Actions выполняет `npm ci`, `npm run build` и публикует `dist` через GitHub Pages. Приложение не требует серверных функций.
